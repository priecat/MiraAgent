    #上层应用接入清单

    按顺序排列的待办清单，逐项完成后形成应用骨架。

    #场景

    基于内核构建应用的接入步骤汇总。清单按执行顺序排列，逐项列出要写的 API、原因与对应文档。

    #清单

    按顺序排列，括号内为这一步产出的内容。

    #1. 声明运行时

    项内容
    做什么KernelRuntime.builder().name(...).dataDir(...).build().start()
    为什么内核的一切都从这套运行时取；数据目录决定文件落哪
    APIKernelRuntime.builder() / KernelRuntime.start()
    文档内核运行时装配

    #2. 设置默认运行时

    项内容
    做什么紧接着 KernelRuntime.installDefault(rt)
    为什么不带 runtime 的上下文会落到默认运行时；晚装会被懒创建的空实例抢先
    APIKernelRuntime.installDefault(...)
    文档内核运行时装配

    #3. 写配置（模型 / 提示词 / 工具来源）

    项内容
    做什么往 rt.declaration() 里写模型、提示词、工具来源、默认模型
    为什么配置快照说明"这个世界有什么"，是后面一切查找的依据
    APIdeclaration().setModels(...) / setEmbeddings(...) / setPrompts(...) / setToolProviders(...) / getAgentConfig().setDefaultModel(...)
    文档配置中心、接入一个模型

    #4. 应用配置

    项内容
    做什么配置写完后调 rt.declaration().applyAllInstance()
    为什么不应用，模型/embedding 不会进注册表，模型列表就是空的
    APIdeclaration().applyAllInstance()
    文档配置中心

    #5. 实现持久化

    项内容
    做什么实现 PersistencePort，挂到 rt.setPersistencePort(...)
    为什么不挂 = 跑完即弃，没有记忆、不能回放
    APIPersistencePort.loadContext / persistContext / appendEvent / ensureSession
    文档消息持久化

    #6. 实现工具包解析（要做编排才需要）

    项内容
    做什么实现 ToolResolver：把"工具包 id"换成"工具名集合"
    为什么编排里按工具包 id 取工具，解析不出就判失败，不猜默认值
    APIExecutionResolver.resolve(blueprint, invocation, toolResolver, declaration)
    文档执行前先校验

    #7. 组装一次对话

    项内容
    做什么建 AgentContextHolder（会话 id、模型别名、提示词、工作空间），再 new AutoAgent(holder) 挂工具
    为什么调用参数说明"这一次怎么跑"，用完即弃，不进配置快照
    APIAgentContextHolder.builder()、AutoAgent.mountToolsIfAbsent(...)、chat(...) / chatStream(...)
    文档基础对话、工具调用

    #8. 把事件推给前端

    项内容
    做什么注册 EventCenter + 监听器，把 AnsResponse 推给前端；先落库再推送
    为什么思考过程、工具调用、正文、结束都靠事件流出；重连时用事件 id 补推
    APIEventCenter.register(...)、DefaultEventListener.sseEmitterSend(...) / onError(...)
    文档流式输出

    #9. 附件与工作空间

    项内容
    做什么用 rt.vfs() 读写会话附件包；用 holder.workspacePath 指定 AI 能直接操作的真实目录
    为什么附件包按会话隔离、懒加载；工作空间给工具一个可读写的根
    APIvfs().load(sessionId) / loadVfs(sessionId)、Workspace.write / readString
    文档会话附件（VFS）、工作空间（Workspace）

    #10. 技能与 MCP

    项内容
    做什么解析本次激活的技能，把技能/MCP 配套工具并进工具白名单；预解析 MCP 配置
    为什么技能让 AI 按需加载"说明书"，MCP 接外部工具服务
    APIAutoAgent.resolveActiveSkills(holder)、AutoAgent.mountSkillAndMcpTools(...)、McpManager.prepare(...)
    文档技能包（Skills）、接入 MCP 工具服务

    #11. 中断与续行

    项内容
    做什么用 EventHook.onBeforeToolCall 决定放行 / 代答 / 挂起；挂起后补结果再续行
    为什么需要人工审批、向用户追问时，不能让对话直接跑完
    APIHookResult.respond(...) / HookResult.suspend()、chatStreamResume() / chatSyncResume()
    文档停止与续跑、工具执行前钩子（EventHook）

    #12. 配置导出导入

    项内容
    做什么导出配置快照给别人用，或导入一份现成配置并检查校验报告
    为什么分发时用引用形态避免泄密；导入时缺什么要能看见
    APIexportDeclaration(CredentialPolicy) / importDeclaration(json) → ValidationReport
    文档配置导出与导入

    #13. 收尾释放

    项内容
    做什么进程退出时 rt.close()
    为什么释放工具/模型注册表与技能仓储持有的文件句柄
    APIKernelRuntime.close()
    文档内核运行时装配

    #最小可用代码

    清单前 7 步连成的骨架，后续步骤按上表文档补全：

    import net.itzq.mira.core.utils.IdGen;
import net.itzq.mira.modules.ai.agent.AgentContextHolder;
import net.itzq.mira.modules.ai.agent.AutoAgent;
import net.itzq.mira.modules.ai.client.config.ModelApiConfig;
import net.itzq.mira.modules.runtime.KernelRuntime;

import java.util.Arrays;

public class AppSkeleton {

    public static void main(String[] args) {
        // 1 + 2：装运行时，立刻设置默认
        KernelRuntime rt = KernelRuntime.builder()
                .name("my-app")
                .dataDir("D:/my-app/data")
                .build()
                .start();
        KernelRuntime.installDefault(rt);

        // 3：写配置
        rt.declaration().setModels(Arrays.asList(ModelApiConfig.builder()
                .alias("deepseek-v3")
                .providerName("deepseek")
                .apiModelName("deepseek-chat")
                .apiHost("https://api.deepseek.com")
                .apiEndpoint("/chat/completions")
                .apiKey(System.getenv("DEEPSEEK_API_KEY"))
                .build()));
        rt.declaration().getAgentConfig().setDefaultModel("deepseek-v3");

        // 4：应用配置
        rt.declaration().applyAllInstance();

        // 5：挂持久化（示例省略实现）
        // rt.setPersistencePort(new MyPersistencePort());

        // 7：组装一次对话
        String historyId = IdGen.uuid();
        AgentContextHolder holder = AgentContextHolder.builder()
                .userId("u1")
                .historyId(historyId)
                .modelAlias("deepseek-v3")
                .prompt("你是一个严谨的助手")
                .vfsId(historyId)
                .build();
        AutoAgent agent = new AutoAgent(holder, "worker")
                .mountToolsIfAbsent(AutoAgent.readOnlyTools().toArray(new String[0]));

        System.out.println(agent.chat("你好，介绍一下你自己"));

        // 13：收尾
        rt.close();
    }
}

    #换个场景怎么改

    应用形态清单怎么裁剪
    只是一个脚本，跑完就走只做 1、3、4、7、13；不挂持久化
    常驻服务、单租户全做；8 改成推给长连接
    多租户 SaaS2 改成"最早期装一套兜底"，其余每处显式 .runtime(rt)，见一个进程里跑多套运行时
    纯对话，不做编排跳过第 6 步
    只做流程编排执行器重点做 3、4、6、8、12；对话组装收敛到节点执行器里

    #顺序错了会怎样

    现象原因修法
    模型列表为空写完配置没 applyAllInstance在写配置之后调一次
    模型列表为空（换写法仍为空）installDefault 晚于第一次读配置把 installDefault 提到最前面
    VFS 未初始化：dataDir 为空没设置默认运行时，或 dataDir 没给启动时设置默认运行时并给数据目录
    会话没有记忆没挂持久化rt.setPersistencePort(...)
    前端工具块一直转圈工具事件没配齐成对每条不进正常流程的分支也补发一对开始/结束
    前端刷新后消息丢了事件没先落库，或没有补推监听器里先落库再推，重连带事件 id 补推
    编排里工具包解析不出来没实现 ToolResolver，或解析失败被吞掉实现它，解析不到就让它失败
    全量工具挂上去后 AI 乱改文件白名单里带了写类工具只用只读集合，或去掉写类工具
    多租户互相看到对方文件数据目录相同，或 context 没显式指定运行时各自 dataDir，每处 .runtime(rt)
